## 1 交付形态

- 用户要把 `beacon-go` 做成跨项目的需求规划底座。
- 第一关是换机器后，只用仓库里的文件读取意图树。

## 2 界面与交互

- `plan tree` 和 `truth tree` 是现有的命令行入口。
- 用户不必为了读需求注册项目或迁移 SQLite。

## 3 业务流转

- 仓库里的意图树 JSON 是需求权威源。
- SQLite 是可重建的索引。
- 无本机账本时，当前 `plan tree` 返回 `store_not_found`。

## 4 边界与不做

- 本任务只读取需求，不改需求正文和冻结历史。
- 并发确认与旧证据复用是另外两关，不计入本任务验收。

## 5 歧义与默认值

- 首批范围：默认先做无账本读取；待确认。
- 版本选择：指定版本就读该版；未指定且只有一版就直接读；多版且无明确当前版时列出候选；待确认。
- 验收入口：默认用现有两个命令做黑盒测试；覆盖读成功、版本歧义和读取不创建账本；待确认。
