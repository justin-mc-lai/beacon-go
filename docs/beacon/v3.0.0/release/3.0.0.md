# Beacon Go v3.0.0

Released: 2026-11-25

## What changed

v3.0.0 is the first stable release of the intent-tree truth kernel. The requirement
model changes from flat sea/lake packages to a single tree:

```
intent → module → feature → touchpoint
```

Every node has an immutable id, a canonical JSON body, a `tree-json-v1` fingerprint,
and a five-state lifecycle (`draft → frozen → implemented → verified → deprecated`).
Sea/lake write entry points (`goal program`, `truth decompose`, `goal parallel-plan`)
are gone; old flat packages import as `feature` nodes through `migrate tree`.

The kernel no longer executes agents. subprocess / profile / ralph executors,
`delegate-ralph`, the read-only HTTP projection, the desktop workspace, and the
kernel LLM client are removed. A host agent does the work and records it with
`goal tick --by`; evidence is registered under an explicit feature or node scope.

## Command surface

Seven user-facing groups:

```
beacon plan        init / tree / expand / apply
beacon truth       create / intent / freeze / node freeze / snapshot / tree
beacon change      request / list
beacon implement   report
beacon verify      audit / leaf / rollup + former qa abilities
beacon release     check / confirm
beacon goal        run / tick / status / complete / ...
```

`qa` is not a command; its capabilities are under `verify`.

## Verification evidence

- `go vet ./...` — green.
- `bash e2e/run_e2e.sh` — full chain PASS on the manual lane.
- `bash e2e/run_dogfood.sh` — badminton tree PASS: 22 nodes, 12 leaves,
  2 snapshots, root `verified`, audit clean.
- `bash scripts/check_kernel_deps.sh` — removed surfaces absent from the binary.

## Known limits

- Orchestrator program internals still compile inside the package (no CLI/API entry).
- `wails.json` remains because it is bound to a frozen desktop truth package.
- The web/desktop surface and HTTP API are not part of 3.0.0.
