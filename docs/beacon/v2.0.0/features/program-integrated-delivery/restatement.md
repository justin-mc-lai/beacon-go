## 1 交付形态
Beacon Go 方案 B：单仓湖间交接、按需并行、海级一次签字。GPT‑6.2 Sol 总调度，经 OpenMausBot 内核群实现和独立验收；验收通过后备份旧二进制、重装本机 CLI 并做安装后验证。

## 2 界面与交互
`program route`、单步 `drive` 和 `drive --until-done` 共用开工判定。路由能查出下游等待原因、各湖工位和可总签的候选提交；海级 `program complete` 负责一次确认。

## 3 业务流转
上游独立 QA 通过且被验提交进入主星后，下游从包含有效上游成果的明确提交启动。单个就绪湖复用主工位；多个改动范围明确、互不重叠的就绪湖用独立卫星工作树并行，合入主星串行。全部选中湖到 `awaiting_release` 且主星候选提交总回归通过，记录一次绑定候选和证据的签字，完成各湖后关闭宿主。

## 4 边界与不做
本轮交付到单仓 Beacon 落账与本机重装。不包括实际部署编排、发布窗口、跨仓发布或回滚；旧 Program 及其审计记录不迁移。

## 5 歧义与默认值
改动范围未知或重叠时串行；合并冲突不放行依赖湖。候选变化须重新验收和确认；同一候选仅因进程中断可续跑，不重复派工或签字。用 `A → B/C → D` 验证等待、真实并行、冲突及恢复，由非实现者提交可复查证据。
