判定：
1) 不是 autotest 把 run 推进到 release。autotest 只写 autotest_executed 与 qa stage_executed，
   不写 gate verdict；qa 出口仍要求本 run 的 formal qa verdict 或 derived 证据。
2) 该 run 的 qa 出口吃的是本 run 的 run-bound qa fact（17:03:46 gate_evaluated），
   非跨 run 回落；seed3 已独立证明跨 run pass 不再泄漏。机制上 qa 出口合规。
3) 但 autotest 不能当作独立验收：它只是证据生产者。该 run 的 qa pass 由
   "QA 复核 · opencode" 签名，既不是 autotest，也不是本验收员；本验收员的独立结论
   只在本文件与 qa-verdict-acceptance-20261111T170825.md 中。
4) 该 run 的推进发生在 17:03，早于本轮验证，且本机默认 CLI (~/.local/opt/beacon-go/beacon)
   是 16:05 构建的 afd5cc7+dirty 旧二进制；所以真实 run 的 release 位置只作状态漂移记录，
   不作为本次修复的运行时证据。修复证据以 §1–§5（当前 HEAD 自建二进制）为准。
5) release 未放行：release_human_confirmed=false，release gate 未评估通过，未打 tag。
