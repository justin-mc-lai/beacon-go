# 技能层对照与「意图为什么会被拖延」诊断

> 日期：2026-10-28 ｜ 对照：Python `skills/beacon/`（22 包，626 KB）vs Go `skills/`（7 包）
> 触发：用户反馈「用起来会拖延、摆烂，没按第一性原理实现」
> 结论：**内核能拦住"没冻需求就写代码"，拦不住"冻了空洞需求然后按最省事的方式实现"。缺口在技能层的合同，不在内核。**

## 2. 四个结构性差异

### 2.1 Python 有「强制渐进加载」，Go 没有

Python `beacon-goal/SKILL.md`：

> ## Mandatory progressive load (do not skip)
> 1. Select **exactly one** primary `mode_id` …
> 2. **Read the mode file completely** before acting.
> 3. Open nested `references/<mode>/…` only when the mode file links them.
> 4. Emit the mode output contract + `mode_id` + `recommended_next_harness`.

Go 改前的 goal SKILL.md 是 5 条命令，**一个字都没提 `references/core.md`**。

后果：约束写在 `core.md`（默认不加载），步骤写在 SKILL.md（总是加载）。宿主只读 SKILL.md，
于是 agent 看到的是"怎么做"，看不到"不许怎么做"。

### 2.2 Python 有「输出契约」，Go 没有

Python 每个公共技能都规定一轮必须交：`mode_id` / `evidence_refs` / `recommended_next_harness` /
`plain_language_delivery_summary`。

Go 改前没有任何输出要求 → **"完成"的定义由 agent 自己下**，最低成本的定义就是"我说完成了"。
这是摆烂的第一性原理：目标函数里没有可验证项，最优解就是少做事。

### 2.3 Python 有「反例与验收」，Go 没有

- `references/examples/`：goal 一包 14 条「30 秒」示例（goal-longrun-30s、hotfix-30s、subagent-*），
  是 few-shot 锚点；
- `references/incidents/`：出过什么事；
- `evals/evals.json`：`"expectations": ["Selects an explicit mode_id", "Does not perform out-of-harness work"]`。

Go 三者皆无 → 没有锚点，模型回落到通用默认行为（少做、说漂亮话、不复核）。

### 2.4 Python 有「路由」，Go 没有

`beacon-gov-router` + `public-surface-progressive-map.v1.json` 负责「用户这句话 → 进哪个技能、加载哪些参考」。
Go 只有 7 个技能平铺，路由靠模型猜 → 用户一句"分析下"，模型选最轻的路径（或不用技能），因为路由成本高于直接答。

## 3. 为什么表现为「拖延、摆烂」

不是模型懒，是**技能的激励结构在奖励"看起来完成"**：

1. 上下文里只有步骤，没有验收 → 完成度不可判 → 取最低成本解释；
2. 没有 `mode_id`/`evidence_refs` 的强制输出 → 无法被追问"证据呢"；
3. 约束默认不加载 → 硬门禁在纸面上存在，在执行时缺席；
4. 没有示例/事故 → 不知道"假交付"长什么样，也就不会自我拦截；
5. 没有 evals → 退化不可观测，连"技能没被遵守"这件事都没人记录。

对照你今天的实际遭遇（前端整块 JS 语法错误却声称完成、Goal 卡硬编码"QA 100% 通过"），
这五条全中：**那不是能力问题，是合同缺失**。

## 4. 对「现有需求意图是否完善」的判断

| 层 | 判断 | 依据 |
|---|---|---|
| 需求真相（数据层） | **完善** | truth 包 + ask→sign→confirm + AC 追溯 + freeze 门禁 + drift 自检；Python 有、Go 也有，且有测试 |
| 执行约束（技能层） | **不完善（改前）** | 技能没把意图翻译成"可拒绝的条件"：无输出契约、无拒绝清单、无强制加载 |
| 路由（意图 → 技能） | **缺失** | 无 router、无 progressive map |

一句话：**意图在数据层是硬的，在执行层是软的。** 内核能让"没冻需求"过不去，但让"冻了一份空话"过得去。

## 5. 今天改了什么（已落地）

给 7 个公共技能统一补四块，并且写进测试防回退：

| 块 | 作用 |
|---|---|
| `## HARD GATE` | 何时必须停：不得自证、不得降门、不得伪造进度；无执行器就停在 `plan` |
| `## Load before acting` | **先完整读 `references/core.md` 再执行**（把约束从"默认不加载"改成"强制加载"） |
| `## Output contract` | 每轮必须交：`mode_id` / `evidence_refs` / `next` / `plain_summary` |
| `## Refuse (no fake delivery)` | 8 条拒绝清单：没读代码不给方案、没跑命令不说通过、只改文档不算完工、不许写"应该/大概"、没冻 AC 不动手、不重复规划、等人不记阻塞、不评估不判 pass |

守卫测试：`skills/contract_test.go` 断言每个 SKILL.md 都含这四块、都要求 `references/core.md`、
拒绝清单至少 6 条编号项。删掉任何一块，`go test ./skills/` 立刻红。

体积：19,921 B → 30,940 B；已用 `--force` 重装到 `~/.workbuddy-ai/skills`（7 技能 / 14 文件）。

## 6. 仍缺（按杠杆排序）

1. **~~examples~~ / ~~evals~~（已补，见 §7）**。
2. **router + progressive map**：用户一句话 → 技能 + 必读参考。没有它，7 个技能仍然是"平铺的菜单"。
3. **14 个 `beacon-gov-*`**：分支、钩子、诊断、状态这些"防跑偏"动作没有技能承载。
4. **modes/patterns/incidents**：Python 的模式库和事故库是长期积累的，迁移是内容工作，不是代码工作。
5. **行为评测**：`qa score` 现在能跑 evals 的机器检查（结构层），但"模型有没有照做"仍需要模型跑一遍 + 人打分（effectiveness 维度）。

## 7. 第二批：examples + evals 已落地（2026-10-28）

每个技能现在带：

```
skills/<id>/
  SKILL.md              合同（HARD GATE / Load / Output / Refuse）
  references/core.md    约束细节
  examples/*.md         3 条 30 秒示例（用户这样说 → 走哪条路 → 产出什么 → 不要做什么）
  evals/evals.json      3 个用例：prompt + expectations + 机器检查
```

`evals.json` 的 `checks` 是**可机器判定的断言**（`contains` / `references_contains` / `min_examples`），
回答"这个技能到底有没有写清它声称的规矩"，不冒充"模型行为对不对"。后者留在 effectiveness 维度由人打分。

`beacon qa score` 因此多了三项结构检查：

| check | 分值 | 含义 |
|---|---:|---|
| `evals_present` | 3 | `evals/evals.json` 存在且 schema 是 `skill-evals.v1` |
| `evals_cases` | 3 | ≥3 个用例，每个有 id / prompt / ≥2 条 expectations |
| `evals_checks_pass` | 4 | 每个用例的机器检查全部通过（失败会点名到 case id） |

第一次跑就抓到一个真问题：`plan` 的用例要求技能里写 "Never answer"，但技能正文没有这句话
（实际写的是 "answer your own question"）——检查断言与技能正文不一致，`evals_checks_pass` 直接 0/4。
改成正文真实存在的表述后 7 个技能全部 100/100。**这就是 evals 的作用：不是给人看的，是给漂移报警的。**

实测（`BEACON_STORE_PATH=/tmp/...`，真二进制）：

```
$ beacon qa score skills/goal --project /tmp/beacon-score --feature demo --evaluator operator
structural     100.00 / 100 (weight 60, mechanical_static)
  [ok] evals_present       3/3  evals/evals.json parses (3 cases)
  [ok] evals_cases         3/3  3 cases, each with id/prompt/2+ expectations
  [ok] evals_checks_pass   4/4  all 8 machine checks pass
effectiveness  not scored (needs a human grade)
total: 100.00  grade: A
```
