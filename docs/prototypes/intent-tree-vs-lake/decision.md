两个领域样本均**通过**：意图树在 4 项指标中 3 项不劣于湖海，且叶子验证绑定率 100%（判定线：≥3 项不劣 + 绑定率 100%）。

| 样本 | 叶子覆盖率（湖海/树） | 歧义点（湖海/树） | 人工修改（湖海/树） | 验证绑定（湖海/树） | 判定 |

## 关键证据

1. **真实引擎两次都给不出模块级拆解**：`raw-engine-lake.json` 中两个样本均为 `journeys=null`、`lakes=null`。羽毛球样本 `truth_readiness.ready=true`，CLI 样本 `ready=false`——同一句“拆不出来”，ready 判定还不一致。
2. **湖海把不同抽象层压进 `feature`**：两个样本都存在“安装与升级”“赛事报名”这类跨多个触点的复合功能，叶子粒度不可判定。
3. **意图树强制叶子给出可执行验证**：羽毛球 26/26、CLI 17/17 带 Given/When/Then 或人工核对步骤；湖海两样本各只有 1 个 feature 带验证规格。
4. **歧义在叶子层被清零**：两个样本的树侧自检各发现 1 个歧义（候补时限、重试上限），补齐后为 0；湖海侧 5–6 个模糊表述没有落点可修。

## 限制（必须与结论一起读）

- 两个样本、单作者；两套拆解均由同一宿主 agent 完成，存在顺序与作者偏差。
- 基准清单先于拆解冻结，降低“照着答案拆”的风险，但基准本身仍由作者拟定。
- 湖海侧真实引擎输出为空，公平对照是手工按现行结构补齐的，不代表引擎能自动产出。
- 人工修改次数各 1 条，统计意义弱。
- 树节点比湖海多约 2–2.5 倍，真实项目维护成本未验证。
- HTML 只是视图，不证明内核能力。
